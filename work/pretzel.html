Overview

Snack was moving fast and every new screen was being designed from scratch. I built Pretzel, a Figma design system based on Apple's Human Interface Guidelines and atomic design. It gave design and engineering one shared source of truth, which cut design debt and build time.

CompanySnack: video-first dating for Gen Z
Stage$3.5M-funded startup
My roleProduct Designer, system owner
PlatformiOS 13+ (iPhone SE and up)
ToolsFigma components, variants, auto-layout, team libraries

01The problem

Fast shipping, slow drift.

At a 10-person startup, speed beats polish, until it doesn't. Each new workstream (onboarding, messaging, the video feed) brought its own slightly different buttons, greys and spacing. Engineers rebuilt the same component again and again, and nobody could say which version was the right one.

/01

No single source of truth

Colours, type and spacing were picked by eye for each screen, so the same intent ended up shipped as several different values.

/02

Rebuilding, not reusing

Without shared components, every handoff meant more one-off UI for engineering to build and maintain.

/03

Growth would make it worse

Accessibility, Dynamic Type and a future Android app would multiply every inconsistency already in the product.

02The approach

Atoms first, screens last.

I structured Pretzel around Brad Frost's atomic design, so each layer only builds on the one below it. Change a colour style once and it flows through every button, card and screen in the Snack files.

Level 1

Atoms

Colour, text and effect styles, plus icons.

Level 2

Molecules

♥  Like

Buttons, badges, toggles and inputs.

Level 3

Organisms

Send

Message tables, nav bars, cards, conversation views.

Level 4

Templates

Screen layouts on the 4pt grid with 16pt margins.

Level 5

Pages

Real Snack screens, built from instances.

i.
Native by default

Apple's HIG for touch targets, type and iOS patterns, so Snack feels at home on the iPhone.

ii.
Accessible for everyone

Dynamic Type support from day one, with contrast and colour-blindness checks using the Stark and Color Blind plugins.

iii.
Minimal and named well

A small, hand-picked palette with predictable names. Fewer choices mean fewer mistakes.

iv.
Built for engineering

Whole-number sizes, heights in multiples of 4, and iOS-only parts labelled for a future Android build.

03Foundations

The dough of the system.

Everything here is interactive. These are Pretzel's actual tokens and rules, rebuilt for the web.

3.1Colour

A "hand-picked" palette named in the colour-### scheme. The names don't encode a use case, which keeps the options open while keeping the number of colours small. Click a swatch to copy its hex.

Transparency comes in 10% steps. Only.

To stop "22% black" turning up in one file and "25%" in the next, Pretzel only allows opacity in 10% increments, and adding a new one needs the design owner's approval. Drag the slider: it snaps to the nearest step.

3.3Grid & the pt system

Design in pt, not px. iOS converts points to pixels at each device's own multiplier, so designs don't depend on pixel density.

06Documentation & adoption

If it's not documented, it doesn't exist.

  • Docs sit next to the components

    Every Figma page pairs a purple documentation panel with the live components: usage, conventions and best practices in one place.

  • No setup needed

    The library was pre-enabled for every Snack team file, so components were already in the Assets panel, ready to drag in.

  • Variants over hunting

    Designers change type, state and size from the right sidebar instead of searching for the right frame.

  • Ready for the future

    iOS-specific parts (status bar, home indicator, keyboard) were labelled so an Android version could swap them later. A governance process based on Brad Frost's was planned for v2.

One source of truth replaced per-screen guesswork. New screens started from instances, not blank frames.

08Reflection

What I'd knead differently.

01Start with tokens in code

Pretzel lived in Figma. Next time I'd export colours, type and spacing as design tokens so Figma and the codebase can't drift apart.

02Put governance in place early

The review process was marked "Future." At startup speed, a lightweight contribution process should come with v1, not v2.

03Measure adoption

I'd track how many components are detached and how many instances each one has, so the system's value can be shown with numbers, not just felt.

04Name things for people

Food-themed naming (Pretzel, Snack, "chef's kiss") made the system something people liked using. Culture is part of adoption.
